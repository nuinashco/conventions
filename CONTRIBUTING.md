# Contributing

How this repo is built and how to change it. Using it: [README.md](README.md). The rules it follows are its own,
[GUIDE.md](GUIDE.md).

## Commands

| command | does |
|---|---|
| `make setup` | `uv sync`, and the pre-commit and commit-msg hooks |
| `make check` | ruff, this repo's own checks, pyright, the unit tests, generated files fresh: what CI runs |
| `make build` | regenerates GUIDE.md, COVERAGE.md and the plugin's skills and subagents from `rules/` and `agents/` |
| `make test-judges` | the judges on their labelled cases (needs the Claude Code CLI, logged in) |

## Layout

```text
rules/                     the source of every rule
  _intro.md                title, how to read, where the other IDs live, retired IDs; `areas` orders the areas
  <area>.md                one area: frontmatter (area, title, skill, description, paths), then its rules
  _decisions.md            contested choices and why
  _sources.md              references
agents/                    subagent prompts, with {{checklist}} and {{rule:ID}} placeholders
src/conventions_hooks/
  settings.py              the [tool.conventions] table: opt-in and ignore
  findings.py              findings, and the command line and Claude hook of the per-file checks
  comments.py              check-comments
  conventions.py           check-conventions
  switches.py              its ARC-9 checks: a variant name switched on in more than one place
  forwarders.py            its ARC-10 check: functions that only forward their arguments
  package.py               the other modules of a file's package, for the checks that look past one file
  waivers.py               `# conventions: <RULE>` comments that waive a rule at one line
  protected.py             check-protected
  commit_msg.py            check-commit-msg
  review.py                review-comments, with doc_rules.md (generated) as its rules
  rules.py                 build-rules
plugins/conventions/       the Claude Code plugin
  .claude-plugin/plugin.json
  hooks/hooks.json         PreToolUse, PostToolUse and Stop hooks, through scripts/run-check
  scripts/run-check        runs the project's .venv/bin/<command>; exits 0 where there is none
  skills/, agents/         generated by build-rules
.claude-plugin/marketplace.json   the nuinashco marketplace: conventions, and nuikit from its own repo
GUIDE.md, COVERAGE.md      generated by build-rules
tests/
  conventions_hooks/       unit tests, test_<module>.py for each module of the package
  test_invariants.py       generated files are fresh; the plugin and marketplace wire real commands and sources
  test_run_check.py        scripts/run-check in projects with and without the command
  judges/                  labelled cases for the LLM judges, and fixture projects they review (`-m judges`)
```

`.gitattributes` marks every generated file `protected=generated`, so `check-protected` refuses agent edits to them.

## Change or add a rule

1. Edit the rule in `rules/<area>.md`, keeping its ID and its shape: a `### <ID> <LEVEL>` heading, the body, a
   `*Why:*` paragraph when there is a reason to give, and a final `*Check:*` paragraph. A new rule takes the next
   free number of its area; an ID is never reused, and a retired one goes in the `retired` list of `rules/_intro.md`.
2. When a tool can decide the rule, add the check (`check-conventions` is the usual home) with its tests, and name it
   in the *Check*; a rule whose every *Check* part starts with "review" stays in [COVERAGE.md](COVERAGE.md), the
   backlog for new mechanical checks.
3. Run `make build`, which regenerates GUIDE.md, COVERAGE.md and the plugin's skills and subagents, and `make test`,
   which fails while any of them is stale.
4. After changing a judge's prompt (`agents/`, the instructions in `review.py`) or its model, run `make test-judges`
   (live `claude` calls: minutes, about $3) and add each mistake it makes as a new case (TOOL-6).
5. Update nuinashco/rnd-template where it implements the rule, commit, and tag a release.

## How the generator reads a rule

A rule is a `### <ID> <LEVEL>` heading (optionally ` [rnd]`), its body, an optional `*Why:*` paragraph and a final
`*Check:*` paragraph. Any other heading of level 1 to 3 outside a code fence is an error, so a mistyped heading cannot
merge two rules. A rule is review-only when every `;`-separated part of its *Check* starts with "review": its skill
quotes it in full, the reviewer's checklist lists it, and COVERAGE.md counts it when it is a MUST. Every other rule
appears in its skill as one line under "Checked by tools", with its summary: the opening sentences of its body until
they hold twenty words, followed by the items of the list they lead in to when they end in a colon. The reviewer's
checklist quotes in full the rules whose *Check* is review only in part.

## Tests

`make test` runs the unit tests and the freshness check, in under a second. `make test-judges` runs the live
judges, which takes minutes and about $3.

Fakes, not mocks. The judge tests seed projects from `tests/judges/fixtures/` and load the subagents from
`plugins/conventions/agents/`; `pytest -m judges --collect-only` shows them without running them.

## Releases

Pull requests are squash-merged with their title as the commit (GIT-3), and their description follows
`.github/pull_request_template.md` (GIT-6); `make github` sets the GitHub repo up that way once.

Tag `vMAJOR.MINOR.PATCH` on `main` once CI passes. Projects pin the tag in `[tool.uv.sources]` and take new checks
by moving it and running `uv lock`. The plugin's skills, subagents and hook wiring follow the default branch, so a
hook command's name and flags never change without a major version.

## Deviations

- **TOOL-1**: `make check` runs no `lint-imports`, and pre-commit has no nbstripout. The package has no subpackages
  for an import contract to order, and the repo has no notebooks.
- **STY-2, LOG-4**: ruff's T201 is ignored for the whole package. Every module is a console script that reports on
  stdout with `print`, and click or rich would become a dependency of every project that installs the hooks.
