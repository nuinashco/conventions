# Contributing

How this repo is built and how to change it. Using it: [README.md](README.md). The rules it follows are its own,
[GUIDE.md](GUIDE.md).

## Layout

```text
rules/                     the source of every rule
  _intro.md                title, how to read, where the other IDs live, retired IDs; `areas` orders the areas
  <area>.md                one area: frontmatter (area, title, skill, description, paths), then its rules
  _decisions.md            contested choices and why
  _sources.md              references
agents/                    subagent prompts, with {{checklist}} and {{rule:ID}} placeholders
src/conventions_hooks/
  settings.py              the [tool.conventions] table: opt-in and ignore
  findings.py              findings, and the command line and Claude hook of the per-file checks
  comments.py              check-comments
  conventions.py           check-conventions
  protected.py             check-protected
  commit_msg.py            check-commit-msg
  review.py                review-comments, with doc_rules.md (generated) as its rules
  rules.py                 build-rules
plugins/conventions/       the Claude Code plugin
  .claude-plugin/plugin.json
  hooks/hooks.json         PreToolUse, PostToolUse and Stop hooks, through bin/run-check
  bin/run-check            runs the project's .venv/bin/<command>; exits 0 where the repo has not opted in
  skills/, agents/         generated by build-rules
.claude-plugin/marketplace.json   the nuinashco marketplace: conventions, and nuikit from its own repo
GUIDE.md, COVERAGE.md      generated by build-rules
tests/
  conventions_hooks/       unit tests, test_<module>.py for each module of the package
  test_invariants.py       generated files are fresh; the plugin and marketplace wire real commands and sources
  test_run_check.py        bin/run-check in projects with and without the opt-in
  judges/                  labelled cases for the LLM judges, and fixture projects they review (`-m judges`)
```

`.gitattributes` marks every generated file `protected=generated`, so `check-protected` refuses agent edits to them.

## How the generator reads a rule

A rule is a `### <ID> <LEVEL>` heading (optionally ` [rnd]`), its body, an optional `*Why:*` paragraph and a final
`*Check:*` paragraph. Any other heading of level 1 to 3 outside a code fence is an error, so a mistyped heading cannot
merge two rules. A rule is review-only when every `;`-separated part of its *Check* starts with "review": its skill
quotes it in full, the reviewer's checklist lists it, and COVERAGE.md counts it when it is a MUST. Every other rule
appears in its skill as one line under "Checked by tools", with its summary: the opening sentences of its body until
they hold twenty words, followed by the items of the list they lead in to when they end in a colon. The reviewer's
checklist quotes in full the rules whose *Check* is review only in part.

## Tests

```bash
make test           # unit tests and freshness, under a second
make test-judges    # live judges, minutes and about $3
```

Fakes, not mocks. The judge tests seed projects from `tests/judges/fixtures/` and load the subagents from
`plugins/conventions/agents/`; `pytest -m judges --collect-only` shows them without running them.

## Releases

Pull requests are squash-merged with their title as the commit (GIT-3), and their description follows
`.github/pull_request_template.md` (GIT-6); `make github` sets the GitHub repo up that way once.

Tag `vMAJOR.MINOR.PATCH` on `main` once CI passes. Projects pin the tag in `[tool.uv.sources]`; the plugin's skills,
subagents and hook wiring follow the default branch, so a hook command's name and flags never change without a
major version.
